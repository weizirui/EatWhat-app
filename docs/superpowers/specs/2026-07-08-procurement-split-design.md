# 已有食材与系统建议购买拆分设计

## 目标

- 让用户在点击“补齐缺失食材”后，能清楚区分哪些食材是自己已有的，哪些是系统建议一起购买的。
- 在页面展示和订单提交时同时保留这种区分，避免“都混成一个总清单”。
- 为后续采购清单、代买、订单处理预留更清晰的数据结构。

## 当前问题

- 现有实现中，点击“补齐缺失食材”会把缺少的食材直接加入已选食材。
- 提交订单时虽然会把食材一并带出，但只能拿到总的 `ingredient_ids`。
- 这样无法区分：
  - 用户原本就有的食材
  - 因为某道菜临时补齐、需要购买的食材

## 设计方案

### 数据结构

- 将食材来源拆成三类：
  - `owned_ingredient_ids`
    - 用户手动选择、表示家里已有的食材
  - `suggested_purchase_ids`
    - 点击“补齐缺失食材”后，由系统建议补齐的食材
  - `all_ingredient_ids`
    - 最终参与匹配和提交的总食材，等于前两者合并

### 交互规则

- 用户手动勾选食材：
  - 进入 `owned_ingredient_ids`
- 用户点击“补齐缺失食材”：
  - 缺失食材进入 `suggested_purchase_ids`
  - 不再直接并入“已有食材”
- 匹配逻辑：
  - 继续基于 `all_ingredient_ids` 计算，保证推荐结果实时变化
- 页面文案：
  - 用户原本选的食材显示为 `已有食材`
  - 系统补齐出来的食材显示为 `系统建议购买`

### 来源迁移规则

- 如果一个原本在 `suggested_purchase_ids` 中的食材，后来被用户手动勾选：
  - 它应自动从 `suggested_purchase_ids` 移除
  - 并进入 `owned_ingredient_ids`
- 如果用户主动删除某个“系统建议购买”食材：
  - 应尊重用户操作，不要立即自动补回
- 如果用户清空食材：
  - `owned_ingredient_ids` 和 `suggested_purchase_ids` 都清空

## 页面改造

### 食材页

- 购物车抽屉中改成两个分组：
  - `已有食材`
  - `系统建议购买`
- 两个分组都支持删除单项。
- 已有食材仍然保留现有卡片风格。
- 系统建议购买可用较轻提示色，表示是系统给出的采购建议，而非用户原始库存。

### 匹配页

- 顶部食材概览卡改成双层展示：
  - `已有：...`
  - `建议购买：...`
- “一键补齐缺失食材”按钮可调整为：
  - `补齐并加入建议购买`
  - 或继续保留原文案，但实际行为改为加入建议购买分组

### 成功页 / 后续订单页

- 如需展示订单食材摘要，可同步分成：
  - 已有食材
  - 系统建议购买

## 订单提交结构

- 提交订单时建议保存：
  - `recipe_ids`
  - `owned_ingredient_ids`
  - `suggested_purchase_ids`
  - `all_ingredient_ids`
- 这样后续无论是人工看单、生成采购清单，还是做履约逻辑，都能直接区分“现有”和“待买”。

## 对现有逻辑的影响

- `utils/store.js`
  - 需要新增对 `suggested_purchase_ids` 的持久化读写
- `pages/home/index`
  - 需要同时读取并展示两类食材
- `pages/match/index`
  - 需要使用合并后的 `all_ingredient_ids` 做匹配
  - 需要修改补齐逻辑，写入“系统建议购买”而不是“已有食材”
- 提交订单逻辑
  - 需要从单一 `ingredient_ids` 升级为三套字段

## 边界处理

- 如果用户没有任何“系统建议购买”，页面不显示该分组或显示为空态。
- 如果“已有食材”和“系统建议购买”出现重复，最终以“已有食材”为准。
- 匹配结果应永远基于合并后的总食材，避免页面看起来有建议购买，但菜谱仍显示“还缺”。

## 测试策略

- 增加 store 层测试，覆盖：
  - 新增建议购买
  - 建议购买转为已有
  - 清空时两组同时清空
- 更新食材页和匹配页模板测试，覆盖：
  - 两类食材分组文案已接入
  - 匹配页顶部概览已显示“已有 / 建议购买”
- 更新订单提交流程测试，覆盖：
  - 提交时同时保存 `owned_ingredient_ids`
  - `suggested_purchase_ids`
  - `all_ingredient_ids`
