# 协作功能上线清单

## 当前互通方式

1. A 在设置页填写协作昵称并生成 6 位邀请码。
2. B 在自己的小程序中填写昵称并兑换邀请码。
3. 云端为 A、B 各写一条方向相反的协作关系，因此双方都能看到对方，也支持各自绑定更多协作人。
4. A 提交清单时只能选择“仅自己保存”或一名协作人，避免多人重复采购。
5. B 打开“设置 -> 查看采购任务”，可看到新任务并更新为“采购中”和“已完成”；A 在“我发出的”中看到同步状态。
6. 如果提交时网络中断，订单详情会保留“重新发送协作清单”；云端按发送者和订单号幂等，不会重复创建任务。

当前已实现的是小程序内任务和未读数。微信聊天列表或系统通知属于订阅消息，需要单独配置模板和用户授权。

发布前必须确认正式小程序到底使用哪个 AppID，并确认该 AppID有权限访问上述云环境。AppID 与云环境不属于同一小程序账号时，邀请码和协作云函数都会失败。

### 2. 创建云数据库集合

- `collab_invites`
- `collaborators`
- `collab_tasks`

集合权限保持“仅云函数可读写”。小程序端不直接读写这些集合。

### 3. 上传并部署云函数

在微信开发者工具中逐个右键以下目录，选择“上传并部署：云端安装依赖”：

- `create_collab_invite`
- `redeem_collab_invite`
- `list_collaborators`
- `submit_collab_order`
- `list_collab_tasks`
- `remove_collaborator`
- `update_collab_task_status`
- `update_collab_profile`

`send_order_kf_message` 是客服消息能力，不属于邀请码与协作任务主链路。

### 4. 双用户验收

1. 用两个不同微信号进入同一个体验版。
2. A、B 分别填写不同协作昵称。
3. A 生成邀请码，B 在 30 分钟内兑换。
4. 确认双方协作人列表都出现对方昵称。
5. A 选菜并把清单指定给 B。
6. B 打开采购任务，依次点击“开始采购”“完成采购”。
7. A 在“我发出的”中确认状态同步。

## 系统消息方案

### 产品实用性

订阅消息可在协作人未打开小程序时提醒“收到采购清单”，比仅有站内未读更及时。它只做提醒，任务数据仍以 `collab_tasks` 为准。

### 长期复用性

后续可复用同一通知入口发送“新任务”和“采购完成”提醒，不改变邀请码、协作关系和任务状态结构。

### 落地成本

需要在微信公众平台申请订阅消息模板，取得模板 ID 和字段定义；接收方还必须主动调用 `wx.requestSubscribeMessage` 授权。拿到模板信息后才能准确接入，不能在代码里猜字段。

### 维护难度

维护量较低，但一次性订阅通常每次授权只支持发送一次。发送失败不能影响清单提交，云函数应记录失败并继续保留站内任务。
